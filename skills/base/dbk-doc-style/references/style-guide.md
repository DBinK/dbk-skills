# 通用写作规则细节

本文件是 dbk-doc-style 的规则全集。检查与生成共用同一套规则。按类别阅读，每条规则给出正反例。

## 一、英文规则

### 1.1 标题 Title Case

标题和副标题中每个主要词首字母大写，虚词（and/or/the/of/in）小写。标题不加句号。

| 错误 | 正确 |
|------|------|
| `How to install the sdk` | `How to Install the SDK` |
| `Setting up your workspace.` | `Setting Up Your Workspace` |

UI 标签、按钮名、短短语同样用 Title Case。

### 1.2 Oxford comma

三个及以上并列项，最后一个逗号保留：

- 正确：`Install the SDK, configure the device, and run the demo.`
- 错误：`Install the SDK, configure the device and run the demo.`

### 1.3 主动语态、现在时

- 正确：`The tool writes logs to /var/log.`
- 错误：`Logs are written to /var/log by the tool.`

### 1.4 简洁用词

| 不用 | 用 |
|------|-----|
| utilize | use |
| in order to | to |
| eliminate | remove |
| inform | tell |
| subsequently | then |

删除冗余副词：quite, very, quickly, easily, effectively, simply。

### 1.5 数字

0–9 拼写（`three devices`），10 及以上用数字（`25 devices`）。度量衡、版本号、百分比用数字（`3.5 kg`, `v2.0`）。

### 1.6 缩写

首次出现写全称加括号缩写（`Software Development Kit (SDK)`），后文用缩写。

## 二、中文规则

### 2.1 全角标点

正文使用全角标点：`，。：！？""''【】`。半角逗号/句号只出现在代码、命令、URL 内。书名号用 `《》`，不要用引号代替。

### 2.2 正文不用分号

中文正文不要用 `；` 连接多个子句。拆成句号或冒号，或改用列表。分号串联通常意味着句子结构臃肿。

| 错误 | 正确 |
|------|------|
| `日志默认关闭；开启后增加磁盘占用。` | `日志默认关闭，开启后会增加磁盘占用。` |
| `配置分三步；第一步是……` | `配置分三步：第一步是……` |

### 2.3 口语化，去公文腔

避免书面套话，用自然的说法：

| 不用 | 用 |
|------|-----|
| 本产品系…… | 本产品是…… |
| 请知悉 | （删掉） |
| 经研究决定 | （直接说结论） |

### 2.4 删冗余

常见的无信息量词，删掉后语义不变：

- 结构冗余：`进行+动词` → 直接用动词（`进行升级` → `升级`）
- 虚词：多余的 `的`、`了`、`所`
- 填充语：`需要注意的是`、`可以`、`对于……来说`
- 堆叠修饰：`非常`、`十分`、`极其`

注意语义保全：`了` 表示完成时态时保留（`已升级到 v2.0` 的 `了` 可删，但 `升级了固件` 的 `了` 表达完成，视语境判断）。

### 2.5 具体对照词表

完整对照见 [zh-colloquial-lexicon.md](zh-colloquial-lexicon.md)。常见高频项：

| 不用 | 用 |
|------|-----|
| 对……进行优化 | 优化…… |
| 实现……的功能 | 支持…… / 提供…… |
| 能够 | 可以 / 能 |
| 关于……方面 | 关于…… / 在……方面 |
| 相关的 | （多数可删） |

## 三、结构与可扫描性

- **短段落**：3–7 行一段，一段一个主题
- **标题前置关键词**：`Installing the SDK` 优于 `The SDK Installation Process`；`安装 SDK` 优于 `关于 SDK 的安装流程`
- **平行标题**：同级标题结构一致（都是动词短语，或都是名词短语）
- **要点前置**：结论先写，细节随后
- **列表优于长句**：三个以上并列项用列表

## 四、一致性与术语

- 同一概念全文同词，不混用（如"固件/韧体""参数/变量"）
- 产品名、专有名词大小写唯一（如 `DeepSeek` 全文一致）
- 团队有术语表则优先查表；没有时建议维护一份，首次遇到的新术语选定一个写法并全文统一
- 中英混排：术语首次出现可用 `中文（English）` 格式标注，后文统一

## 五、读者边界

- **写明可依赖程度**：用户能做什么、数据可靠到什么程度，写清楚。例：`该功能仅支持 Windows 10 及以上`，不要只写 `该功能已支持`。
- **不绝对承诺**：避免"保证""永不""绝对"；用"建议""默认"等留出余地
- **不拟人化**：设备/软件没有主观意图。`系统会判断超时` → `系统在超时后执行……`
- **内部信息不泄漏（对外文档）**：内部代号、未定稿状态（已定稿/未验证/测试中/待披露）、内部工具名、产线流程、commit hash、PR 号。内部文档不受此限。
- **已评审的限定词保留**：改写时不要把别人评审过、有意保留的限定词（"目前仅支持 X"）删掉，那可能是有意为之的信息边界。
