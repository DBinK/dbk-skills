# 全局启用

`description` 只能覆盖约八成任务：纯产出、纯分析、生活类请求（写首诗、看报表、查日程）常不触发，因为模型判定「不需要专门规则」。想让本技能每次任务前都在，把下面这段写进当前 Agent 的全局指令文件。

## 待写入的内容

```markdown
<!-- dbk-agent-rules -->
任何任务开始前，先加载 `dbk-agent-rules` 技能并按其准则执行——包括提问、查资料、分析、写作、改文件、跑命令、做判断在内的一切场景，不限于写代码。即使用户没有提到「规则」「习惯」「约定」，即使看不出与该技能的直接关联，也不要跳过。
<!-- dbk-agent-rules -->
```

## 全局指令文件位置

各客户端各自为政，没有跨工具标准——`agents.md` 规范只定义仓库内的 AGENTS.md。

| 客户端 | 全局指令文件 |
| --- | --- |
| Codex | `~/.codex/AGENTS.md` |
| opencode | `~/.config/opencode/AGENTS.md` |
| Claude Code | `~/.claude/CLAUDE.md` |
| pi | `~/.pi/agent/AGENTS.md` |

## Agent 的做法

1. 判断自己在哪个客户端（看系统提示或工具集），判断不出就直接问用户
2. 报出要改的全局文件路径，说明写入哪段内容（整段给出）以及是追加还是新建
3. **等用户确认后再动手**。目标文件已有内容时先读出来，把这段追加进去，不要覆盖
4. 说清代价：强制加载不看相关性，连「嗯，好的」这类没有请求的消息也会把本技能拉进上下文
5. 写完告诉用户改了哪个文件、怎么撤销

表里没有的客户端：让用户查该客户端的文档确认全局指令文件位置，不要猜。
